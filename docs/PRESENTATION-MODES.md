# Presentation Modes

The channel isn't faceless-only. Every project picks one of three presentation modes, and the
system must never hard-code around any single one of them (`packages/shared/src/enums.ts` is the
source of truth: `PRESENTATION_MODES`, `SEGMENT_TYPES`, `PRESENTATION_MODE_SEGMENT_PRIORITY`,
`recommendPresentationMode`).

| Mode | Meaning | Never... |
|---|---|---|
| `FACE_LED` | Creator on camera through most of the video - talking-head hook, explanation, reactions, verdict. | ...forced off-camera. |
| `HYBRID` | Creator on camera where it adds trust/personality; screen recordings and graphics carry the rest. This is the channel's default. | ...forced to stay off-camera *or* on-camera for the whole runtime. |
| `FACELESS` | Narration, screen recordings, product outputs, and graphics carry the video. | ...required to produce on-camera footage. |

## Where it lives

- `projects.presentation_mode` (enum) + `projects.presentation_mode_is_recommended` (bool) - the
  second flag tracks whether the current value is still a system recommendation the creator hasn't
  overridden, or a mode they picked explicitly.
- `video_ideas.recommended_presentation_mode` - the Idea Research Agent's own per-idea
  recommendation, based on how personality-driven that specific angle is (an "I gave the same task
  to X and Y" idea reads differently from a dry tutorial, even within the same project).
- `reference_videos.presentation_mode` + `reference_videos.on_camera_segments` - the Competitor
  Analyst's reverse-engineering of a reference video's *own* mode and exactly where/why its
  creator appears on camera (hook, reaction, verdict, ...). This informs but never dictates this
  project's mode.
- `production_scenes.segment_type` - one of `ON_CAMERA | VOICEOVER | SCREEN_RECORDING |
  PRODUCT_RESULT | B_ROLL | MOTION_GRAPHIC | SCREENSHOT` per scene. This is what actually drives
  behavior everywhere else (which Remotion component families apply, whether an A-roll shot gets
  planned, whether "assets ready" tracking includes it).
- `aroll_shots` - the on-camera shot list, generated by the Production Director only for scenes it
  marked `ON_CAMERA`, and only ever for `FACE_LED`/`HYBRID` projects (see `docs/DATABASE.md`).

## Recommend, never require

1. `recommendPresentationMode(contentType)` seeds a starting guess for a brand-new project when
   the creator leaves the wizard's presentation-mode field on "Recommended" (the Start New Video
   wizard, `apps/web/src/app/(app)/projects/new/page.tsx`). It never returns `FACE_LED` on content
   type alone - nothing about a content type by itself should force heavy on-camera time.
2. Once the creator selects an idea, `selectIdea()` (`packages/agents/src/domain.ts`) refines the
   mode to that idea's own `recommendedPresentationMode` - **but only while
   `presentationModeIsRecommended` is still true**. The moment a creator calls
   `setPresentationMode()` (via the Overview tab), that flag flips to false and nothing
   auto-adjusts the mode again.
3. `setPresentationMode()` is the only function allowed to write `projects.presentation_mode` -
   like stage transitions, this keeps one code path responsible for a field the rest of the system
   trusts.

## How it changes agent behavior

- **Production Director** (`packages/agents/src/runners/production.ts`): builds a scene list
  where `segmentType` varies by mode. A `FACELESS` project's runner output is validated to
  guarantee zero `ON_CAMERA` scenes (`runAgent`'s `validate` callback rejects the output
  otherwise - a defensive check even though the fixture/prompt shouldn't produce one). A
  `FACE_LED` project gets an additional on-camera explanation beat a `HYBRID` project skips. Every
  `ON_CAMERA` scene also gets a matching row in `aroll_shots`, generated in the same call.
- **Asset Planner** (`packages/agents/src/runners/assets.ts`): only ever plans
  `SCREEN_RECORDING`/`GENERATIVE` requirements - on-camera capture is the Production Director's
  responsibility, tracked separately in `aroll_shots` with its own `MISSING/READY` status so it
  doesn't get silently conflated with B-roll.
- **Next Action Engine** (`packages/shared/src/next-action.ts`): at `ASSETS_REQUESTED`, the next
  action names both missing assets *and* missing A-roll shots together
  (`missingArollShotCount`), and the stage can't auto-advance to `ASSETS_READY` until both are
  zero (`apps/web/src/lib/project-readiness.ts`).

## UI surfaces

- **Start New Video wizard**: a presentation-mode select defaulting to "Recommended for this
  content type".
- **Project header / dashboard cards**: a presentation-mode badge next to the stage badge.
- **Overview tab**: shows the current mode, whether it's a recommendation or an explicit choice,
  and a form to change it at any time.
- **Production Script tab**: a segment-type badge per scene (`ON_CAMERA` scenes read distinctly
  from `SCREEN_RECORDING`/`VOICEOVER` ones), plus notes for `screenInsertInterrupts`, `punchIn`,
  and any `pictureInPictureLayout`.
- **A-Roll tab**: hidden behind an explanatory empty state for `FACELESS` projects; otherwise the
  full on-camera shot list with a "mark filmed" action per shot, matching the product spec's
  A-ROLL 001 example almost field-for-field.
- **References tab**: shows each reference video's own presentation mode and its reverse-engineered
  on-camera timeline.
- **Ideas tab**: shows each idea's recommended presentation mode.

## Remotion components for on-camera treatments

See `docs/REMOTION.md` for the full catalog. The presentation-mode-specific additions:
`TalkingHeadFrame` (full-bleed on-camera shot with a caption-safe band - the default `ON_CAMERA`
treatment), `PictureInPicture` (face inset over a screen recording), `CreatorLowerThird` (name/context
strip reminding the viewer who's narrating without a full inset), `CreatorReaction` (a small
reaction bubble for a quick genuine reaction beat), `ScreenAndFaceSplit` (50/50 split for
simultaneous explanation + demonstration), `PunchIn` (a frame-based zoom for emphasizing a static
on-camera shot instead of cutting away), and `ArollToDemoTransition` (a directional wipe bridging
on-camera and screen-recording beats).
