1. What is Headroom?

Headroom (headroom-ai on PyPI) is a free, open-source tool (Apache-2.0 licence) that compresses everything your AI agent reads — tool outputs, logs, files, search results and conversation history — before it reaches the model. The idea: same answers, fewer input tokens.

  • Works with coding agents like Claude Code, Codex, Cursor, Copilot, OpenCode and Aider.
  • Zero code changes: one command "wraps" your agent so its traffic goes through Headroom.
  • Runs on your machine: the README says compression is local and no prompt or file content is sent anywhere to be compressed.

2. What does it actually save?

Scenario (from the project's own benchmark)Tokens saved
Code search (100 results)21%
SRE incident debugging57%
Codebase exploration42%

Be realistic: savings depend on how repetitive the input is. The README says repeated JSON and log lines compress a lot (90%+ in its benchmark), while normal prose and already-compact output compress very little. Measure your own with headroom savings.

4. Install and wrap Claude Code

  1. Install uv by following docs.astral.sh/uv, then check: 
    uv --version
  2. Install Headroom (the README's recommended command for coding agents): 
    uv tool install --python 3.13 "headroom-ai[all]"
    Using pip instead: pip install "headroom-ai[all]"
  3. Start Claude Code through Headroom: 
    headroom wrap claude
    This starts a local proxy and launches Claude Code routed through it. Use this command each time you start a session (the wrap is session-scoped and stops when the agent exits).
  4. Check it works: 
    headroom doctor
  5. Watch the savings (while a wrapped session or proxy is running): 
    headroom dashboard
Undo anytime: headroom unwrap claude removes the setup. Other agents work the same way, e.g. headroom wrap codex or headroom wrap cursor (Cursor needs a manual settings step — see the README's Agent compatibility table).
Want it always on? The README describes headroom deploy for a turnkey local setup that survives reboots. Start with wrap first so you can see the difference.

5. Tips

  • Try it on a log-heavy task (running tests, debugging errors) — that's where repetitive output, and the biggest savings, come from.
  • Compare a normal session and a wrapped session on the same task, and check headroom savings.
  • If anything looks off, run headroom doctor and check the README's troubleshooting section.
  • Commands change between releases: always check the README on GitHub.
